MCP Hub — Agentic Flow Architecture

End-to-end pipeline for parsing, enriching, and saving API definitions via a state-machine orchestrator

8 Agents 5 LLM Calls State Machine Orchestrator Human-in-the-Loop (HITL) Deterministic Anchoring
1. Entry Points — How a Session Starts
Entry Mode A
📄 File Upload
User uploads a document (PDF, DOCX, OpenAPI spec, Postman collection). File is saved to disk and path stored in session.
POST /api/agent/upload
PDF DOCX OpenAPI JSON OpenAPI YAML Postman JSON TXT / MD HTML
Rate limit: 10/min per user
Entry Mode B
💬 Chat Message
User pastes raw API documentation as natural language or structured text. Stored as raw_input in session.
POST /api/agent/chat
Natural Language Raw Markdown Inline JSON Curl examples
Rate limit: 60/min per user
Entry Mode C
📝 Manual Form
User fills a structured form with API name, base URL, endpoints and parameters. Skips LLM pipeline entirely — goes straight to validate → test → save.
POST /api/agent/manual
name base_url auth_type endpoints[] parameters[]
Rate limit: 30/min per user

Phase 1 — Pre-HITL Pipeline Fully automated. Runs on session start. Returns to user at HITL_PENDING.
🔍
Agent 1 · State: CLASSIFYING
InputClassifier
agents/input_classifier.py
Gateway agent. Determines whether the session should be processed as a document upload (DOC) or a chat message (CHAT), so downstream agents know which parsing path to take.
Input
session.file_path — path to uploaded file (if any)
session.raw_input — chat text (if any)
Logic
If file_path exists on disk → mode = "DOC"
Otherwise → mode = "CHAT"
Output
session.mode = "DOC" | "CHAT"
No LLM
📖
Agent 2 · State: PARSING
ParsingAgent
agents/parsing_agent.py
Extracts raw content from the source document and splits it into per-endpoint chunks. Structured formats (OpenAPI, Postman) are chunked deterministically; unstructured formats (PDF, DOCX) use a 2-pass LLM extraction.
Input
session.file_path or session.raw_input
Process (Structured)
doc_extractor reads JSON/YAML → detects OpenAPI or Postman
smart_chunker splits at operation object level — no LLM
Process (Unstructured)
Pass 1: LLM extracts endpoint index (method + path list)
Pass 2: LLM extracts full details per endpoint (parallel)
Output
session.extracted_schema._chunks[] — one entry per endpoint
session.extracted_schema.base_url, .auth_type, .name
LLM (unstructured only)
🧬
Agent 3 · State: SCHEMA_GENERATING
SchemaAgent
agents/schema_agent.py
The core enrichment agent. Converts raw endpoint chunks into clean, OpenAPI-compatible definitions. Uses a deterministic extractor as an anchor to prevent LLM hallucinations, then lets the LLM fill in names, descriptions, and inferred schemas.
Input
session.extracted_schema._chunks[]
Process (per endpoint, ≤8 concurrent)
deterministic_extractor → GroundTruth (method, path, params) — LLM cannot override
LLM enrichment: function name, description, request/response JSON Schema
endpoint_validator auto-fixes hallucinations, adds missing params
Also Produces
Coverage report: matched vs total_reference endpoints
Validation reports: per-endpoint fix history
Output
session.draft_api — full API definition with endpoints[]
session.validation_reports[], session.coverage_report
LLM — meta + per-endpoint enrichment
🔗
Agent 4 · State: RECONCILING
ReconciliationAgent
agents/reconciliation_agent.py
Consistency pass over all generated endpoints. Fixes duplicates, aligns auth types, and normalises naming conventions across the entire API — ensuring a coherent, non-contradictory output.
Input
session.draft_api.endpoints[]
Pass 1 — Deterministic
Deduplicate: remove exact method+path duplicates
Align auth: inherit API-level auth for blank/UNKNOWN endpoints
Normalise names: majority convention (camelCase vs snake_case) wins
Pass 2 — LLM (≤20 endpoints only)
Cross-endpoint consistency: naming, auth alignment, contradictory descriptions
Preserves method and path (anchors remain untouched)
Output
session.draft_api.endpoints[] — deduplicated and normalised
LLM (conditional — ≤20 endpoints)
📊
Agent 5 · State: CONFIDENCE_SCORING
ConfidenceAgent
agents/confidence_agent.py
Scores every field in the draft API for HITL highlighting. The UI uses these scores to show the user which fields need manual attention. HIGH = trust it, MEDIUM = review it, LOW/MISSING = fix it.
Input
session.draft_api
session.validation_reports[] (auto-fix history from SchemaAgent)
Scoring
Meta fields (name, description, base_url, auth_type): LLM scores 0-100
Endpoint fields (path, method, input_schema, output_schema): rule-based
Auto-fixed fields: score reduced (fixes are a signal of lower reliability)
Score Levels
HIGH ≥80 MEDIUM 50–79 LOW <50 MISSING 0
Output
session.confidence_map — keyed by field path, e.g. "endpoints.0.input_schema"
LLM — meta field scoring

👤 State: HITL_PENDING

Pipeline pauses, session returned to user
Frontend shows draft API + confidence scores
Low-confidence fields highlighted for review
User edits any field inline
User can provide auth credentials (Bearer token, API key)

📡 Resume Route

POST /api/agent/{id}/hitl
edits: {} — partial or full overrides to draft_api
auth_credentials — for live testing
save_anyway: bool — override test warnings
POST /api/agent/{id}/confirm (no edits shortcut)

🔀 Other Actions

POST /api/agent/{id}/discard — mark DISCARDED
POST /api/agent/{id}/restart — discard + re-run full pipeline with same source
Edits are shallow-merged: top-level fields replaced, endpoints array supports index-based partial updates
Phase 2 — Post-HITL Pipeline Runs after user confirms. Validates → tests → saves. Can return to HITL_PENDING if issues found.
✅
Agent 6 · State: VALIDATING
SchemaValidator
agents/schema_validator.py
Rule-based guard. Checks that the final API definition meets hard structural requirements before allowing it to proceed to testing or saving. No LLM involved — purely deterministic.
Input
session.final_api (draft merged with user edits)
Rules Checked
API name — required, non-empty
API base_url — required, valid http/https URL
At least one endpoint required
Each endpoint: path starts with "/", method is GET/POST/PUT/DELETE/PATCH
Each endpoint: name required, auth_type valid enum
On Failure
Session returns to HITL_PENDING with validation_errors shown
Output
session.validation_errors[] — empty = valid
No LLM
🧪
Agent 7 · State: API_TESTING
ApiTestAgent
agents/api_test_agent.py
Live-tests the API endpoints before saving. Makes real HTTP calls to GET endpoints (with test params) and uses LLM to assess whether the response matches the declared schema. POST/PUT/PATCH/DELETE are always skipped to avoid side effects.
Input
session.final_api
session.auth_credentials (decrypted, per-endpoint or shared)
Strategy
GET, no auth → real HTTP call with synthetic params
GET, with auth → call if credentials available, else SKIPPED
POST / PUT / PATCH → always SKIPPED (avoid side effects)
DELETE → always SKIPPED (destructive)
Verdicts
PASS WARNING UNREACHABLE AUTH_REQUIRED SKIPPED
On WARNING/UNREACHABLE
If save_anyway=false: returns to HITL_PENDING with test results
If save_anyway=true: continues to SAVING regardless
Output
session.api_test_results[] — verdict, status_code, url_tested, duration_ms, issues[]
LLM — response assessment
💾
Agent 8 · State: SAVING
ApiSaver
agents/api_saver.py
Persists the validated, tested, human-approved API definition to the database. Creates ApiDefinition and ApiEndpoint records, encrypts auth credentials, and sets session state to SAVED.
Input
session.final_api
session.auth_credentials (per-endpoint or shared)
Process
Create ApiDefinition record (id, name, description, base_url, visibility="PRIVATE")
For each endpoint: create ApiEndpoint record (input_schema, output_schema, headers)
Encrypt auth_credentials before storing (per-endpoint or shared mode)
Commit database transaction
Output
session.api_definition_id — UUID of saved API
Database: ApiDefinition + ApiEndpoint rows created
session.state → SAVED
No LLM
5. Orchestrator — State Machine Controller
agents/orchestrator.py — owns all session lifecycle. Agents never talk to each other directly; everything flows through the orchestrator via a shared AgentSession object.

Key Methods

start(raw_input, file_path)
→ Creates session, runs full pre-HITL pipeline, returns at HITL_PENDING
confirm(session, human_edits, save_anyway)
→ Merges edits, runs post-HITL pipeline
discard(session)
→ state = DISCARDED, no further work
restart(session)
→ Discard old, create new session, re-run pre-HITL
_merge_edits(draft, edits)
→ Shallow merge; endpoints support index-based partial updates
_run_step(session, fn, state)
→ Wraps each agent; catches exceptions → FAILED + friendly error

Error Handling

Any exception inside an agent is caught by _run_step(). The exception is converted to a friendly message via _friendly_error(), recorded in session.error_log, and the session state becomes FAILED. No 500 response is raised — the error is surfaced to the user through the session object.

Multi-Tenancy

Sessions are scoped to user_id. All router endpoints verify that session.user_id == current_user.id — a 404 is returned if a user tries to access another user's session. Auth credentials are encrypted at rest and decrypted only inside ApiTestAgent and ApiSaver.
6. Utility Modules — Supporting Infrastructure
doc_extractor.py
Reads any file format and returns plain text or structured data. Used by ParsingAgent.
Formats: PDF (pypdf), DOCX (python-docx), JSON, YAML, TXT, MD, HTML
Returns: (text: str, fmt: "openapi_json"|"postman"|"text")
Extras: JSON repair (closes unclosed brackets/braces)
smart_chunker.py
Splits API documentation into per-endpoint chunks using format-aware strategies. Used by ParsingAgent.
Structured: object-level split — no LLM needed
Unstructured: 2-pass LLM — index extraction then details
Returns: (base_info{}, [EndpointChunk{method, path, hint, content}])
deterministic_extractor.py
Extracts method, path, and parameters WITHOUT an LLM. Produces the "anchor" data that prevents hallucinations in SchemaAgent.
JSON chunks: parses OpenAPI operation objects
Text chunks: regex for path params {tokens}, query patterns, auth headers
Returns: GroundTruth(method, path, path_params, query_params, headers, body_schema)
endpoint_validator.py
Validates LLM-generated endpoints against GroundTruth and auto-fixes discrepancies. Used by SchemaAgent.
Fixes: corrects method/path, adds missing path params (required=true), coerces invalid JSON Schema types, falls back to ground-truth body schema
Returns: (fixed_endpoint, ValidationReport{is_valid, was_auto_fixed, issues[]})
endpoint_coverage.py
Compares reference endpoints from source file against generated endpoints to measure completeness.
Matching: exact (method + path) + relaxed (same method, different param names)
Coverage % = matched / total_reference
Returns: CoverageReport{matched, missing, extra, coverage_pct}

8. Anti-Hallucination Strategy

⚓ Deterministic Anchoring

Before any LLM call in SchemaAgent, deterministic_extractor extracts method, path, path params, query params, and headers using pure regex/JSON parsing. These become the "GroundTruth" anchors. The LLM is given these anchors and told it cannot change them. After the LLM responds, endpoint_validator enforces this — correcting any deviation.

🤖 LLM Roles

The LLM is only trusted to fill in things it cannot make factually wrong: function names (from operationId hints), natural-language descriptions, and inferred schemas for request/response bodies. Structural data (paths, HTTP methods, parameter names) is always derived deterministically.
